# Prompt 1 — Foundation

You are building **ShopAssist**, an Expo (SDK 58) + TypeScript shopping app. Read `docs/SPEC.md` fully before doing anything — it is the source of truth. Also read `AGENTS.md` and follow it: Expo APIs change every SDK, so check the versioned docs at `https://docs.expo.dev/versions/v58.0.0/` (and `https://docs.expo.dev/llms.txt`) before using any Expo / Expo Router API instead of relying on memory. The original template code is in `example/` (git-ignored) — use it as a reference for this SDK's patterns (e.g. `NativeTabs` in `example/src/components/app-tabs.tsx`).

This prompt builds the **foundation only**: project memory, theme, types, seed data, data layer, stores, providers, navigation shell and base components. Do **not** build full screens yet — that is Prompt 2.

Work through the steps in order. Don't stop to ask me questions; make sensible decisions, note them, and keep going.

## Step 2 — Seed data (real product images, demo data)

Write `scripts/build-seed.mjs` (Node, no extra deps) that:

1. Fetches `https://dummyjson.com/products?limit=0` (free demo product API with matching images and reviews).
2. Keeps about **48 products** from these categories (fall back to similar ones if a name differs): `smartphones`, `laptops`, `mens-shirts`, `womens-bags`, `kitchen-accessories`, `beauty`/`skin-care`.
3. Maps each to the `Product` type in the spec:
   - `price` = round USD price × 85 to an integer ending in 9 (e.g. 12,499); `mrp` = price ÷ (1 − discountPercentage/100), rounded up to ending in 9.
   - `id` as string, `specs` from brand / weight / dimensions / warranty / shipping / return policy fields, `tags`, `stock`.
   - `reviews` from DummyJSON reviews (give each an id and `verified: true`). Then add **4–6 extra realistic reviews per product** generated by the script from simple templates mixing positive and negative points relevant to the category (e.g. battery, fit, fabric, sound), so the review summary has something to work with. Include at least one critical (≤ 3 stars) review per product.
   - Mark 6 products across categories as `sponsored: true`.
4. Writes `src/data/products.json` and `src/data/categories.json` (slug, name, product count).

Run it once and commit the generated JSON. Add a header comment in the script saying the data is demo data from DummyJSON.

## Step 3 — Types and utilities

- `src/types/index.ts`: all types from the spec (Product, Review, CartItem, Order, OrderStatus, Address, ChatMessage, BuyerInsights, Insight) plus `ProductQuery` (search, category, minPrice, maxPrice, minRating, sort, page, limit) and `Paginated<T>`.
- `src/lib/format.ts`: `formatPrice` (INR, en-IN, no decimals), `discountPercent`, `formatDate`.
- `src/lib/pricing.ts`: `getPriceBreakdown(items)` → `{ subtotal, delivery, total, freeDeliveryRemaining }` with free delivery at ₹499+, else ₹49. This is the single source of truth for prices everywhere (cart, checkout, order).
- `src/lib/haptics.ts`: thin wrappers (`tap`, `success`, `warning`, `longPress`) over expo-haptics that no-op on web.

## Step 5 — Data layer

- `src/lib/api.ts`: an `Api` interface matching the spec's endpoints (getProducts, getProduct, getSimilar, getInsights, getCategories, parseSearch, ask, registerDevice, createAlert, createOrder, getOrders, getOrder).
  - `httpApi` uses `process.env.EXPO_PUBLIC_API_URL`.
  - `mockApi` uses `src/data/*.json` with simulated latency (300–700 ms), real filtering / sorting / pagination, and simple deterministic stand-ins for AI endpoints:
    - `getInsights`: pick pros from 4–5★ reviews and cons from ≤3★ reviews by keyword, each with the review ids it came from.
    - `ask`: keyword-match the question against title/description/specs/reviews; if nothing matches return `grounded: false` with "That isn't in the product details or reviews."
    - `parseSearch`: extract price ("under 2000"), category words and rating ("4 star") with regex.
  - Export `api` = httpApi if the env var is set, else mockApi.
- `src/lib/queries.ts`: TanStack Query hooks — `useProducts(query)` (infinite), `useProduct(id)`, `useSimilar(id)`, `useInsights(id)`, `useCategories()`, `useOrders()`, `useOrder(id)` — with sensible `staleTime` and query keys.
